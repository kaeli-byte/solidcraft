## Review round 1

Independent reviewer `sb14-reviewer` (fresh context) returned APPROVE with three should-fix
findings and five notes; no blocking defect was found. The reviewer re-ran the contract suite (27
passed at the reviewed commit), the service feasibility domain tests and the feasibility route test
against a throwaway database, clippy and fmt on both crates, and `git diff --check`. All findings
are addressed at head 60a1a44c7:

- R1 the locked applicability model could not express the supplied corrugated radius table, which is
  keyed by connection-area inside diameter: `FeasibilityTubeAttributes` and `RuleApplicability` gain
  an explicit `nominal_connection_size_mm` condition matched exactly, with tests for the failing and
  passing bend and for the unresolved result when the reviewed nominal connection size is absent. The
  contract's applicability table and corrugated-source paragraph record it.
- R2 hostile input was bounded only after evaluation: `evaluate_feasibility` now projects the finding
  count and the rule-finding work and refuses an assessment over `MAX_FINDINGS_PER_ASSESSMENT` or
  `MAX_EVALUATION_WORK` before allocating, with a many-bend/large-table test.
- R3 the registry paragraph miscounted contract versions and mis-stated where the feasibility routes
  live; both statements are corrected.
- Note: `AssessmentRecorded` now carries `non_passing_finding_count` so it is not read as open work.
- Note: an exception is accepted against the latest recorded assessment only; a superseded
  assessment or a changed supporting review is `422 invalid`, covered by store tests.
- Note: the contract handoff now tells the desktop mapping to call `TubeExtraction::validate` and
  require `algorithm_is_current`, and tells SB-19 that an empty issue list is not assessment
  coverage.
- Note: supporting measurement `field_path`s now use the evidence wire field names
  (`bend_radii_mm[i]`, `tangent_straight_lengths_mm[i]`, `straight_end_lengths_mm[i]`).
- Note: the API route test now asserts the identical-retry replay and the `409 conflict` of both new
  write routes.
