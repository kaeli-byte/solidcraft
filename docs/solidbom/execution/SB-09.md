### Review round 1

The independent reviewer returned `CHANGES` on local head `3e6443ad5` against merge base
`3c355556b2`. Each finding was judged against the code and dispositioned:

- **R1 (blocker), fixed:** a percentage base with `direct_cost: true` could also name a
  `Direct(material)` or `Direct(production)` category, counting that direct cost twice. The
  contract now rejects that overlap in `AppConfigVersion::validate`, with a contract unit test and a
  service API rejection case; the setup subtotal is outside the direct-cost subtotal and remains
  allowed.
- **R2 (should), fixed:** the publish form cleared when the asynchronous request was submitted, so
  a later 409 or network failure lost the draft and both `clear_*` methods reset the other form's
  edits. Now only the submitted form is marked awaiting; it clears solely after that request's
  successful completion, a failure keeps both drafts, and each form clears only its own fields. A
  unit test covers in-flight, failure and success.
- **R3 (should), fixed:** the material and rate selectors showed only names, so two versions of one
  record were indistinguishable. Both selectors now label every version with its number, purpose
  and price/rate (missing reads as missing), and a UI test selects the second version of a chain
  and asserts the exact version id reaches the reviewed inputs.
- **R4 (nit), declined:** the reviewer's GitHub, Cargo-lock and filesystem limitations are
  properties of its sandbox, not of this change. The revision carries recorded local checks and
  the pull request's GitHub CI; re-running the named suites in a writable environment is the
  reviewer's step and no code change addresses it.
