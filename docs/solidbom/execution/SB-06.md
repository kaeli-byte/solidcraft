## Checkpoint

SB-06 implements the nonblocking controller around the integrated SB-01 host seam, SB-03 service,
SB-04 extraction/mapping adapter and SB-05 read-only binding. Implementation commits:
`fe43c0665` (background analysis and controller) and `9bcc6ea0` (headless MCP settle), on branch

SB-03/SB-05 merges). The prerequisite merge commits were verified as ancestors of `origin/main`
on 2026-11-08: SB-03 `d0591450` (PR #41), SB-04 `8e728860` (PR #43), SB-05 `b7f96438` (PR #44);
version 1 contracts are pinned at `1ab7b3b2`.

What changed:

- **Background local analysis** (`crates/engine/src/solidbom/jobs.rs`): the import scratch session
  (`doc.open` + exact extraction) runs on a worker thread with a bounded one-job-per-session
  queue. `solidbom.import` answers at once with the additive `ImportReply.state = "importing"`;
  the review phase is `importing` until an answer is published. A completion is published only
  while the design-replacement counter and the reviewed-binding generation still match the
  submission and the answer's `AnalysisKey` matches its request; otherwise it is discarded and
  the live session is left exactly as it was. A spawn failure is `EngineError::Capability`, never
  a synchronous fallback; a worker that panics or disconnects is a reported failure. `Session::cancel_solidbom`
  drops a pending analysis too, and `replace_design` discards one that belonged to the replaced design.
- **Reopen in the background**: a reopen keeps the loaded project (`phase: importing`) until the
  downloaded source verifies its SHA-256 and is analysed. The verified mapping and UUIDs are then
  restored with the policy binding; a saved analysis from an older engine build/extractor is
  re-analysed in place, keeping the engineer's reviewed inputs and manual measurements, marking
  the project dirty/stale and allowing Calculate (which saves first). The saved calculation
  history stays readable.
- **Runtime map consumption**: every import and reopen rebuilds SB-04's `RuntimeOccurrenceMap`;
  occurrence selection maps runtime CAD ids through it to stable source paths instead of walking
  the tree, and the verified reopen test proves every saved source path maps to a live runtime
  occurrence and back.
- **App polling** (`crates/ui-egui/src/solidbom/jobs.rs`): one frame drains local analyses per
  session and service completions per host, cancels authoring when a binding replaces the design,
  and requests repaints while either kind of work is pending. The BOM workspace shows the pending
  `Importing` state instead of offering the empty start again.
- **Headless MCP** (`crates/mcp/src/backend.rs`): the headless session has no window frames, so it
  waits for a background analysis (also between script steps) and returns the import reply in the
  pre-SB-06 shape; the windowed control channel stays frame-polled and never blocks.
- **Real service test** (`apps/solidcraft/src/solidbom_client.rs`, `service_tests`): import,
  review, save, calculate, refused stale write, reopen in a fresh session, verified mapping,
  restored inputs, readable history and read-only policy, all against a real development service
  on a fresh database. A stalled service request maps to a visible network (timeout) failure.

Known limits are recorded in the pull request: the controlled analysis delay used for the
before/after visual evidence is a measurement hook, not production behaviour; P13 wall-clock
evidence on the declared test Mac belongs to SB-08; and the coordinator still has to reconcile

  compatible output field, documented in `contracts/v1/commands.md` with the background-analysis
  dispatch path. No command id, input schema or no-undo/batch rule changed.
- `solidbom.import` now returns before the definitions exist; callers poll `solidbom.state`/
  `solidbom.parts`. The UI and the windowed control channel poll per frame; the headless MCP
  backend waits so its tool result keeps the old shape. `Session::wait_solidbom_analysis` and
  `Session::run_script_headless` are the public seams for other headless embedders.

  service's `SOLIDBOM_DELAY_MS`; it changes no result and is capped at 60 s.
