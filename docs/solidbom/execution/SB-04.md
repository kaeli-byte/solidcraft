## Mapping algorithm and version

Extraction version: `EXTRACTOR_VERSION = "2"`; engine build is the engine crate version. Every
analysis and measurement carries `AnalysisKey { source_sha256, engine_build, extractor_version }`.

- **Source path**: the child-index path of an occurrence relative to the import root, joined with
  `.`; the import root's own definition is the empty path. Child indices come from the source
  tree, so the same bytes always produce the same paths.
- **`definition_id`**: UUIDv5 in namespace `736f6c69-6462-6f6d-5f61-6e616c797369` of
  `<source_sha256>:def:<path>`.
- **`occurrence_id`**: UUIDv5 in the same namespace of `<source_sha256>:occ:<path>`.
- **`part_version_id`**: UUIDv5 in `Uuid::NAMESPACE_OID` of `<source_sha256>:part:<definition_id>`
  (unchanged command-layer derivation).
- Runtime CAD component, body, face and edge ids are generated by the importer and are never
  persisted as identity. `runtime_ids_change_but_the_source_map_is_stable` imports the same bytes
  into a session with non-fresh ids: the generated ids differ, while the stable ids, source paths
  and pick results are identical.
- **Runtime-to-source adapter**: `solidcraft_engine::solidbom::extract::RuntimeOccurrenceMap` maps
  runtime occurrence ids to stable source paths and back. `RuntimeOccurrenceMap::new(session)` walks
  the occurrences inside the reviewed import root; `source_path(runtime_id)` and
  `runtime_occurrence(path)` are `Result`-based and refuse ids or paths the import does not place.
  SB-06 must rebuild the map after every import or reopen and persist only the stable source path
  or contract id. The type is exported from `solidbom::extract`; `solidbom/mod.rs` is not edited
  because it is a shared file outside this package's ownership.
- **Picks**: `resolve_pick(session, manifest, Sel)` resolves occurrence, body, face and edge picks.
  A body/face/edge pick of a part placed more than once is refused, never guessed. It refuses a
  manifest whose `AnalysisKey` differs from the session's `ReviewPolicy` analysis, so a stale
  analysis cannot resolve a pick against another source or another extraction. A definition-only
  tree pick uses `solidcraft_engine::solidbom::extract::resolve_definition_pick(manifest,
  definition_id)`, which returns `DefinitionPick { definition, occurrences }` and never invents an
  occurrence.
- **Measurement**: one exact B-rep `ModelBody::measure()` per definition body, with closedness from
  the existing `encloses_volume` check. A definition is measurable only when every body is present,
  closed and measured in full; otherwise `volume_mm3` is `null` with named issues. The volume is the
  definition's own volume; quantity is the occurrence count and is never folded into measurement.

## Unsupported and degraded cases (SB-06 handoff)

- **Open or mixed closed/open component**: `volume_mm3` is `null` with `open_body` and
  `missing_volume`; the part stays review-required until an engineer completes the measurement
  manually. Never inferred zero and never a partial closed-body sum.
- **Repeated subassembly instances**: a STEP tree that places one *subassembly* more than once is
  not fully represented yet. The current importer keeps one occurrence slot per repeated
  subassembly and walks its children only under the first placement
  (`crates/engine/src/cmd/file_import.rs`, `walk`), so extraction sees each child once, under the
  first parent. Quantity and world placement for children of a repeated subassembly are therefore
  incomplete. The repeated leaf-part case (the same part placed four times, including nested under
  subassemblies that are themselves placed once) is correct and covered by `nested_repeated.step`.
  The import receipt / mapping extension required by the SB-01 contract is therefore: the import
  boundary must keep per-instance placement identity (an occurrence entity id on the imported node,
  or an import receipt that lists every STEP placement), or extraction must expand effective
  placements through `Document::placements`/`body_frames_with_source` and walk each instance's
  children. Until that extension lands, SB-06 must not treat occurrence quantities as complete for
  such STEP trees, and a repeated-subassembly fixture plus acceptance test are the follow-up.
- **Flat or hierarchy-less input**: one definition with all flat bodies, `unresolved_grouping`
  issue; geometry and import structure are preserved; no component identity is invented from body
  count. The grouping editor remains MVP work outside the prototype.
- **Grouping assembly with no bodies**: extraction builds parts only from components that own
  evaluated bodies, so a component that owns none gets no definition row and no occurrence row at
  all; its children keep their source paths but `parent_occurrence_id` becomes `None`, because the
  empty placement has no reviewed occurrence. Do not expect a `null`-volume row for a grouping
  assembly, and do not price it as a part.
- **Stale or missing source key**: a saved analysis from another source or extractor does not
  match; reopen keeps the source read-only but reports the parts need review and never reuses a
  saved measurement silently. Picks against a stale manifest are refused.
- **Ambiguous pick**: a body/face/edge pick of a part placed more than once is refused with a
  "select an occurrence" error; a definition-only pick returns the definition and its occurrences
  without inventing one.
- No claim of actual customer-file accuracy, automated recognition or P13 timing is made by this
  package.
