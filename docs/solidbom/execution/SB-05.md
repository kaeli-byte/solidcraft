The implementation reuses the existing reviewed-source seam instead of adding a parallel gate:

- `crates/engine/src/solidbom/policy.rs` is the explicit, default-deny policy. It adds the bound
  reviewed original's path (`with_source_path`, `source_path`) and a parameter-aware refusal
  (`refusal_for`) so allowed save/export commands cannot write over that original, directly or
  through an equivalent path. Import and reopen are no longer members of an allowed `solidbom.`
  prefix: the business commands are enumerated, so a new command is denied until it is reviewed.
  Named-view creation, rename and delete are denied because they change the document (and push an
  undo step); `component.hide_history`/`show_history` are no longer allowlisted for the same
  reason.
- `crates/engine/src/lib.rs` makes the binding a policy generation (`bind_review` bumps
  `review_generation`) and composes the policy with the host's `set_command_check` seam:
  `execute` asks the review policy first, on canonical command id and parameters, then the host.
  Prepared feature-editor transactions (`ComputedCommands`) carry the generation they were
  computed under and are refused at `accept_commands` when the policy moved or the session is
  bound; `restore_editor` (Cancel) is refused too because it writes the old design directly
  without a command. The host can never re-enable editing through its own check.
- `crates/engine/src/cmd/solidbom.rs` and `crates/engine/src/solidbom/state.rs` make import and
  reopen atomic: the source is opened and extracted in a session of its own and only a complete,
  verified review is adopted, with the policy bound in the same step. A failed open, extraction
  or SHA-256 verification leaves the live design exactly as it was.
- `crates/engine/src/render_preparation.rs` refuses a prepared render command through the same
  policy and refuses to finish a capture prepared under an earlier policy generation.
- `crates/ui-egui/src/lib.rs` guards every interactive start path, not only `start`: the toolbar's
  direct `start_at`/`start_pinned` calls, the deferred/after-roll/view-confirm `start_interactive`
  path, shortcut starts, and direct feature-editor restoration (`edit_feature_at`, hence the
  timeline double-click, the context menu's Edit Feature and the control channel's
  `ui.editFeature`). A policy binding cancels dialog, tool, prepared editor, queued and computing
  authoring work and runs the same per-document reset an opened design gets. The generation check
  is scoped to the session it started in, so a tab cycle (Ctrl+Tab, `view.next_tab`) is not taken
  for a policy change.
- `crates/ui-egui/src/documents.rs` cancels authoring state for a background tab whose reopen
  completion binds the policy; `crates/ui-egui/src/control.rs` reports refusals for the
  control/MCP start and edit methods, and cancels the replaced design's authoring state when a
  control script binds the policy. `open_review_tab` now opens the imported source under the
  embedder's pre-command check.

## Safe-save path rules for SB-06

The reviewed original is recorded by the trusted local import path and never by a command. In a
bound session:

1. `file.save_as`, `file.export`, `file.export_step`, `file.export_stl`, `file.export_3mf`,
   `file.export_obj`, `file.export_urdf` and `file.save_mesh` are allowed; `file.save` is not.
   The import/reopen paths clear the session's path, so the reviewed source is never the default
   save target; `file.save` stays denied because a reviewed session's working file is kept with
   Save As (a deliberate default-deny choice, not because a save target could be the source).
2. The `path` parameter is compared with the reviewed original before anything is written. The
   refusal is `EngineError::Refused` with a message containing `would overwrite the reviewed
   source`, and the source bytes stay unchanged. Equivalent paths are covered: the same path
   written differently (relative, `.`/`..`), an existing symbolic link to the source, a hard link
   (Unix file identity), another case of a name that resolves to the same file on a case-insensitive
   file system (including a name that no longer exists, on macOS and Windows), and a path whose
   parent directory resolves to the source's directory. A path that does not exist cannot
   overwrite the original and is compared lexically only for the same-path case.
3. Writes elsewhere are ordinary working copies: the reviewed session keeps its own `.sc` save
   and its own exports, and these never make the source dirty. `file.save` remains denied; Save As
   is the working-copy save.
4. Unrelated write commands (`library.export`, `settings.profile.export`, `sketch.export`, render
   image export and so on) stay denied by the default-deny allowlist; they are not part of the
   reviewed session's safe working set. Named-view creation/rename/delete and component
   history hiding are denied because they change the document.
5. No command unbinds, weakens or replaces the policy. `read_only` (the opened-design flag) stays
   a separate concern and is not used as this policy.
6. A reopened project has no local original on this machine: the service stores the source bytes
   and hash, not the path they came from. `ReviewPolicy::source_path` is `None` after a reopen, so
   rule 2 cannot protect a file that was imported earlier in another session. This is a stated
   limitation rather than a silent bypass; persisting an origin path would be a contract change.

## Contract changes and follow-up

No published version 1 contract changes: command ids, parameters, output schemas, host trait and
envelope semantics are untouched. The additions are internal engine API used by the window:
`ReviewPolicy::with_source_path`/`source_path`/`refusal_for`/`source_refusal`,
`solidbom::READ_ONLY_REASON`, `Session::review_generation`/`review_locked_reason`/
`review_refusal_for`, `ComputedCommands`' generation check, the `restore_editor` guard, and the
window's `review_binding`/`design_replaced` helpers. They are additive.

Remaining unclosed points after the independent review and its fixes:

- Render preparation: the generation check at finish is defense in depth; the policy denial of
  render commands is what a bound session reaches in practice. No end-to-end prepared-render test.
- `accept_commands`' generation branch (as opposed to its bound-session branch) is defense in
  depth: a bound session is refused a few lines earlier, and nothing unbinds while keeping a
  prepared transaction. The bound refusal is what the tests exercise.
- Queued/concurrent file loads during a binding are not exercised end to end; a queued insert
  would run on a policy-carrying scratch session and be refused.
- A local CAD save worker in flight when a binding happens is not separately exercised (import
  cannot start while `app.saving` is set, and a reopen binding does not touch it).
- A host that binds a session directly outside `run`/`finish_render_preparation`/
  `advance_solidbom` would not get the window's authoring-state cancellation; every in-tree
  binder goes through those paths.
- The import/reopen prepared `doc.open` runs on a bare session: a context-sensitive embedding
  command check is asked, but sees less session state than a direct `doc.open` would.
- Reopen loses the local original path (safe-save rule 6).
- The executed evidence is the implementation commit; the full `cargo xtask ci` gate result on
  this host is limited by the accepted SB-00/SB-01 baseline failures.
