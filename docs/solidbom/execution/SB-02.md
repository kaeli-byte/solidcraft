The brief's prose name `ResolvedCalculationInput` is the published exact contract
`solidbom_contract::CalculationInputs` (one `ResolvedPartInput` per part); the answer is
`solidbom_contract::CalculationOutcome`. The public API stays
`calculate(&CalculationInputs) -> CalculationOutcome` and
`calculator_version() -> &'static str`, returning `solidbom-direct-cost/1`.

What changed in the package's crate:

- The arithmetic is proven, not changed: volume to mass with the selected density, allowance once
  on material, the explicit material-overhead rate, per-piece production from cycle/cavities and
  the hourly rate, the unrounded per-part subtotal expanded by occurrence quantity, and setup as a
  separate charge counted once per shared part routing.
- Named issues now cover unsupported input as well as missing input: `unsupported_currency` (any
  currency other than the prototype's CNY; FX is out of scope) withholds every amount, and
  `duplicate_part_version` withholds the assembly and setup totals so a shared routing cannot be
  charged twice.
- Aggregate overflow is named instead of silent: the old code returned `None` from a failed
  assembly or setup `checked_add` with no issue. Part overflow issues now name the affected line
  (`parts[i].net_mass_kg`, `allowed_material_cost`, `material_overhead`, `production_cost`,
  `per_part_subtotal`, `line_total`).
- An omitted cavity count is a single-cavity tool, matching the handover's divide-only-when-greater-
  than-one rule; zero cavities stay invalid. A zero quantity withholds the expanded line total, and
  an empty part list withholds the assembly and setup totals instead of reporting a zero cost.
- The crate documentation publishes the formula set, the complete issue-code/field table, the
  missing-versus-explicit-zero rules, the checked-decimal boundary, the excluded categories and the
  calculator-version policy for SB-03.

No contract or root-manifest change was needed. The crate and its tests are the package's dedicated
files; the only other edit is this record.
