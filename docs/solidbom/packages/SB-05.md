# SB-05 — Immutable reviewed-source policy

## Objective

Prevent modeling, source replacement and hierarchy changes in a bound review session across interactive and programmatic entry paths while preserving permitted inspection and normal unbound editing.

## Requirements

Read [Prototype specification](../requirements/cost_calculator_handover/DESKTOP_PROTOTYPE_SPEC.md) and [application specification](../requirements/cost_calculator_handover/APP_SPECIFICATION.md). The application specification overrides compatible workbook formulas; proposals are not approved behavior. The original technical implementation plan is background evidence; package boundaries and current-code corrections in these briefs govern execution. Own P14 source-policy behavior. The existing `read_only` flag only prevents overwriting an opened design and is not this policy.

## Dependencies

Depends on: SB-01

Dependencies mean integrated predecessor work, including transitive predecessors, not a concurrent agent’s promise or an unreviewed artifact.

## Scope

- Reuse/compose the parameter- and session-aware `Session::set_command_check` seam with explicit per-session source binding and a default-deny reviewed command policy. Preserve any embedding host policy.
- Guard interactive starts and host-dispatched operations as well as `Session::execute`; do not use command `.noundo()` or an ID prefix as proof of safety.
- Cover scratch copies, replacement, file workers, tab switches, direct editor restoration and prepared-command adoption. Cancel pending authoring state at review binding and reject results prepared under an earlier policy generation.
- Permit checked selection/view/measurement and separate local working-file saves. Validate path effects so save/export cannot overwrite the bound original, including equivalent paths; normal commands cannot disable protection.
- Keep annotations and business edits outside source geometry. Do not lock unrelated editable tabs: the current host command check follows the host across tabs.

## Interfaces

Implement the SB-01 reviewed binding/policy contract using command ID, parameters and session context, with stable refusal codes/messages. Extend trusted import/adoption integration only through reserved boundaries. The import path binds review mode atomically after successful source verification; policy changes invalidate prepared authoring work. Publish a tested command/entry-path matrix and safe-save path rules for SB-06.

## Ownership

Own `crates/engine/src/solidbom/policy.rs` and policy tests in existing area test modules. Reserve `Session`, command admission, prepared-work adoption, UI start/editor/document/file-load gates and shared module declarations with the coordinator before editing. Do not alter SB-04 extraction or SB-06 business controller code. Work in the dedicated user-created Conductor workspace assigned to this package. Do not rename its branch without an explicit request. Only one package owns a shared file at a time; ask the coordinator to reserve an integration edit before changing an unlisted shared file. SB-00 owns shared execution/bootstrap documents. Never modify generated files. Run `cargo xtask ci` before every commit; do not treat a package-specific check as a substitute. Do not claim unrun tests passed.

## Acceptance

- Deny modeling, transforms/reparenting, parameter changes, undo/redo and source replacement through execute, shortcuts, interactive starts and control/MCP; source/document/manifest state stays unchanged.
- Test scratch/replacement and tab transitions, queued import, pre-binding prepared work, editor cancellation/restoration and protected-path save/export.
- Allowed selection, navigation, exact measurements, annotations through the business seam and separate local save remain usable.
- An ordinary unbound session still models; an existing embedding policy remains effective. Test both reviewed and editable tabs in one host.
- Run focused engine/UI/control suites and record every P14 path actually exercised.

## Assignment gate

SB-01 must be integrated with policy and application-command contracts published. Coordinator assigns/reserves the shared engine/UI integration paths before implementation; SB-04 source-mapping internals are not a dependency and must not be assumed available.

## Handoff

Provide integrated commit, binding/admission/adoption APIs, allowed/denied command matrix, reserved-file release, test evidence and any unclosed bypass. An untested entry path is a remaining issue, not a passing immutable-source claim.
