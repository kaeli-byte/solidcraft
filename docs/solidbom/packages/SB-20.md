# SB-20 — Dependency updates and adoption

Status: planned; not ready for assignment.

## Objective

Make updates visible and deliberate while recalculating affected drafts consistently and preserving accepted history.

## Requirements

Read [APP_SPECIFICATION](../requirements/cost_calculator_handover/APP_SPECIFICATION.md), sections 6 and 13, O06 and scenarios 18–19. Dependency tracking fields are proposed mechanics to lock, not an implicit product-policy expansion.

## Dependencies

Depends on: SB-18, SB-19

Consume integrated scenario baselines, activation records and underlying reference/cost contracts.

## Scope

Identify projects dependent on updated catalogs, rates, rules, routing templates and app configuration. Explain impact and require explicit adoption before shared changes enter draft calculation. Forecast/scope edits instead automatically recalculate affected project draft demand/costs and flag scenarios. Preserve accepted and historical snapshots. Reading a notification does not adopt it; missing draft inputs cannot be replaced by stale current-looking results.

## Interfaces

Lock dependency keys, version-change facts, impact reports and explicit adopt/recalculate commands. Define complete draft-generation publication and stale scenario/result markers so late responses cannot overwrite newer state. Reuse immutable calculations and concurrency/idempotency contracts; no silent background mutation retry or authoritative offline sync.

## Ownership

Own proposed dependency/impact/adoption modules and update UI/controller with area tests. Reserve event adapters in SB-09/SB-10/SB-15, shared snapshot schemas and calculation orchestration changes. Do not independently alter their domain rules. Own `execution/SB-20.md` only.

## Acceptance

- A catalog change flags only dependent projects; viewing the alert leaves versions/results unchanged. Adoption plus recalculation creates a new result.
- Forecast or exclusion changes recompute aggregate shared demand before downstream draft costs and flag saved scenarios; accepted results remain byte-equivalent.
- Missing inputs produce incomplete draft results, while obsolete job completions and failed adoption leave the last saved state intact. Capture alert/adoption/stale-state evidence and run service/controller tests.

## Assignment gate

Require integrated SB-18/SB-19, locked impact/adoption/generation contracts, reserved shared integrations and an assigned base commit. Record choices for proposed acknowledgement/status details before assignment.

## Handoff

Record dependency coverage, adoption/state transitions, versioned test fixtures, actual checks and evidence. Supply SB-21 precise selected/current/stale baseline semantics and SB-22 update-recovery cases.
