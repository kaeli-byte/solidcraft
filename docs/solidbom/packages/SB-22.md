# SB-22 — MVP acceptance and operating handoff

Status: planned; not ready for assignment.

## Objective

Verify the integrated confirmed MVP and provide reproducible operating and recovery instructions without unsupported readiness claims.

## Requirements

Read [APP_SPECIFICATION](../requirements/cost_calculator_handover/APP_SPECIFICATION.md), confirmed sections 1–15 and acceptance scenarios 1–20, plus [DESKTOP_PROTOTYPE_SPEC](../requirements/cost_calculator_handover/DESKTOP_PROTOTYPE_SPEC.md) P01–P14. Proposed scenario clauses require their recorded contract resolution.

## Dependencies

Depends on: SB-13, SB-21

Verify the entire transitive dependency graph is integrated; recognition and commercial/export paths must both be present.

## Scope

Run end-to-end engineering, costing, scenarios, activation, permissions, dependency adoption, exports and recovery checks. Reconcile requirement coverage with actual commits and evidence. Publish startup, database migration/reference management, backup/restore, failure recovery and known-limit instructions for the agreed deployment. Do not add installers, browser parity, NPV, multi-organization behavior or SB-X01 to the MVP gate.

## Interfaces

Consume package contract versions, acceptance fixtures and handoffs. Produce a requirement-to-test/evidence matrix, integrated build/version manifest and explicit pass/fail/unrun report. Lock operating-test boundaries and supported deployment evidence before assignment; fixes belong to the responsible package or separately reserved repair scope.

## Ownership

Own MVP acceptance scenarios, evidence index and operating handoff documentation. Do not change feature modules, shared contracts or CI while acting as acceptance owner without a new reservation. The coordinator alone updates `EXECUTION.md`; this owner maintains `execution/SB-22.md`.

## Acceptance

- Execute all confirmed application scenarios against real desktop/service/storage, including partial deliveries, shared activation, aggregate demand, price/tooling examples and selected-snapshot exports.
- Exercise permission denial, lost replies, stale versions/results, disconnect/retry, process restart and restore with retained original sources/accepted calculations.
- Record independent dimensional/recognition evidence against agreed targets and rerun relevant prototype regression checks. Run required root/service checks; every skipped/failed requirement remains explicit and blocks its readiness claim.

## Assignment gate

Require integrated SB-13/SB-21 and transitive predecessors, locked acceptance/deployment contracts, independent references and agreed coverage/performance targets, reserved evidence scope and an assigned base. No acceptance by document inventory, unit tests alone or unreviewed branch status.

## Handoff

Record tested integrated commit, environment, exact commands/results, real screenshots/recordings and operating/recovery instructions. Coordinator records prototype, engineering/costing and full MVP readiness separately; only verified integrated evidence supports MVP acceptance.
