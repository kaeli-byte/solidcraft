# SB-14 — Feasibility rules and exceptions

Status: planned; not ready for assignment.

## Objective

Evaluate sourced engineering limits and retain unresolved findings or justified exceptions without inventing compliance.

## Requirements

Read [APP_SPECIFICATION](../requirements/cost_calculator_handover/APP_SPECIFICATION.md), section 9, O08 and scenario 10; [DESIGN_RULES_REFERENCE](../requirements/cost_calculator_handover/DESIGN_RULES_REFERENCE.md). Source applicability restrictions remain binding.

## Dependencies

Depends on: SB-09, SB-11, SB-12

Use integrated authorization/reference data, reviewed component associations and exact measurements.

## Scope

Provide structured rule tables for each bend radius, straight tangent spacing, tube/connector compatibility and end assembly length. Administrator-entered limits retain source references. Missing limits and conflicting applicable rules stay unresolved; Administrator resolves conflicts, with no hidden priority/interpolation. Engineers may accept exceptions with recorded justification. Rules remain independent of selected manufacturing cost centers; a general formula builder is excluded.

## Interfaces

Lock applicability/limit types, result states, supporting-measurement references and justified-exception commands. Expose readiness findings for SB-19. The accepted package plan requires review when supporting inputs change; lock exception invalidation mechanics and any extra audit fields explicitly rather than silently promoting specification proposals.

## Ownership

Own proposed feasibility evaluator, rule-maintenance/review adapters and area tests. SB-09 owns shared reference/version authorization; SB-11/SB-12 own review/extraction. Reserve rule-schema migrations, shared finding types and readiness integration. Own `execution/SB-14.md` only.

## Acceptance

- Test every radius independently and measure bend spacing tangent-to-tangent; inapplicable material/dimension limits cannot pass a check.
- Missing spacing/connector data yields unresolved, not pass. Conflicting overlapping limits require resolution or the justified-exception route.
- Record justification and visible exception status; supporting-geometry changes request review under the locked contract. Show findings in native evidence and run evaluator/API/permission checks.

## Assignment gate

Require integrated predecessors, locked rule/result/exception contracts, supplied radius-source applicability and reserved shared files. Missing further numerical limits are handled by unresolved states, not invented defaults. Resolve any proposed exception lifecycle before implementation.

## Handoff

Record imported rule provenance, unresolved data prerequisites, exception/invalidation contracts, readiness outputs and actual test/evidence results for SB-19/SB-22.
