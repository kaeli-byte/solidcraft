# SB-09 — Shared data and permissions

Status: planned; not ready for assignment.

## Objective

Provide shared company reference data with Engineer/Administrator authorization and immutable versions used by projects.

## Requirements

Read [APP_SPECIFICATION](../requirements/cost_calculator_handover/APP_SPECIFICATION.md), sections 1, 8, 10–13, O10/O13 and acceptance scenario 18. Confirmed requirements override handover defaults; proposals remain proposals.

## Dependencies

Depends on: SB-08

The starting commit must contain the integrated prototype and its acceptance handoff.

## Scope

Implement combinable Engineer and Administrator permissions within one organization. Engineers work on projects; Administrators maintain versioned component/material catalogs, cost centers and app cost configuration. Preserve prices, currencies, units, source/version references and project overrides. Supply reference-version boundaries consumed by later routing/feasibility packages. Do not silently update project inputs. Multi-organization onboarding and machine-rate derivation are excluded.

## Interfaces

Lock authorization actions and shared-record/version identifiers before assignment. Provide typed reference list/read/create-version operations and project-selectable immutable versions, with explicit monetary units and configured category bases. Preserve historical reads after a new version is published. Emit reference-change facts for SB-20 without implementing its project-adoption workflow here.

## Ownership

Own proposed server `shared_data` and `authorization` modules, administrative client/controller modules and existing tests for those areas. Shared contracts, migrations, reference seeding, command registries and host wiring require coordinator reservations; do not change them concurrently with SB-10. Own only this package's execution record.

## Acceptance

- Exercise Engineer-only, Administrator-only and combined permissions through API and UI/programmatic paths; hiding a button is insufficient enforcement.
- Revising a price or rate leaves an existing project snapshot unchanged; explicit zero and missing values remain distinguishable.
- Reject ambiguous percentage bases or circular/duplicate category inclusion. Capture genuine administrative UI evidence and run relevant root/service gates.

## Assignment gate

Not ready until SB-08 is integrated, permission/reference contracts and migrations are locked, shared edits are reserved, and an owner/worktree/base commit is recorded. Numerical company defaults require supplied data; prototype fixtures are not defaults.

## Handoff

Record commits, schema/contract versions, authorization matrix, reference fixtures, executed checks and evidence in `execution/SB-09.md`. List consumers and change-event semantics. Branch tests alone do not establish integrated verification.
