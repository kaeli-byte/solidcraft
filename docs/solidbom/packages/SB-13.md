# SB-13 — Recognition and catalog suggestions

Status: planned; not ready for assignment.

## Objective

Suggest extensible component classifications and catalog matches while keeping engineering confirmation authoritative.

## Requirements

Read [APP_SPECIFICATION](../requirements/cost_calculator_handover/APP_SPECIFICATION.md), sections 7–8, O07 and scenario 9. The confirmed initial categories are tubes, connectors, fittings, clips, wear protection and thermal protection.

## Dependencies

Depends on: SB-09, SB-11, SB-12

Consume integrated catalog versions, reviewed associations and verified extraction results.

## Scope

Implement classification and catalog suggestion pipelines with evidence shown for review, correction and bulk confirmation through SB-11. Support adding categories without redesigning project identity. Keep confirmed catalog references and project overrides distinct. Unconfirmed suggestions cannot supply authoritative price/specification inputs. Automatic training, deployment and silent reclassification of existing projects are excluded.

## Interfaces

Lock suggestion records keyed to source/analysis, part version and catalog/model version, plus review command integration. Separate proposed label/match from accepted engineer decision. Define prediction-version/provenance fields as technical contracts; do not treat unapproved model-management proposals as product policy.

## Ownership

Own proposed recognition and catalog-matching modules with their suggestion UI adapter and area tests. SB-11 retains confirmation/training-example storage; SB-09 retains catalog maintenance. Reserve shared review/contract extensions and registry wiring before editing. Own `execution/SB-13.md` only.

## Acceptance

- Predictions remain pending even at high confidence; confirmation/correction updates the shared reviewed record without changing source geometry.
- An unconfirmed connector suggestion cannot contribute catalog price or engineering limits. A confirmed override retains the original catalog version/value separately.
- Evaluate agreed classification/matching coverage against independent labels, report errors and unsupported cases, and capture native review evidence. No inferred accuracy percentage or automated deployment claim is permitted.

## Assignment gate

Require integrated predecessors, independent reference labels, agreed recognition coverage/accuracy targets, locked suggestion/evidence contracts and reserved files. If algorithm/model selection is unresolved, settle it before assignment rather than leaving an agent to invent an acceptance target.

## Handoff

Record model/rule versions, independent dataset provenance, measured outcomes, review-path tests and native evidence. Document category-extension boundaries and limitations for SB-22.
