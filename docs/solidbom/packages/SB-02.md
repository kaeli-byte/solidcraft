# SB-02 — Prototype pure cost engine

## Objective

Implement deterministic backend arithmetic for the approved direct-cost subtotal and separate setup charge, independently of UI, networking and persistence.

## Requirements

Read [Prototype specification](../requirements/cost_calculator_handover/DESKTOP_PROTOTYPE_SPEC.md) and [application specification](../requirements/cost_calculator_handover/APP_SPECIFICATION.md). The application specification overrides compatible workbook formulas; proposals are not approved behavior. The original technical implementation plan is background evidence; package boundaries and current-code corrections in these briefs govern execution. Own arithmetic coverage for P04, P05, P07, P08 and P09. Use the workbook formula references only where compatible with the approved prototype.

## Dependencies

Depends on: SB-01

Dependencies mean integrated predecessor work, including transitive predecessors, not a concurrent agent’s promise or an unreviewed artifact.

## Scope

- Implement the version 1 resolved-input calculator in `crates/solidbom-costing/`; the desktop must never call it for authoritative costs.
- Convert reviewed volume to mass with the explicit selected density, apply material allowance once, apply the explicit material-overhead rate, calculate production cost from per-piece seconds/hourly rate, and expand unrounded part cost by occurrence quantity.
- Count a shared part routing setup once, independently of occurrence count; keep it outside unit direct cost.
- Return named missing-input and unsupported-input issues with unavailable affected totals. Apply SB-01 operation validation for zero versus omitted cycle/setup values. Use checked decimal arithmetic and no company defaults.
- Exclude tooling, SG&A/other full-manufacturing categories, pricing, EBIT, productivity, FX and shared-demand policy from this prototype calculator.

## Interfaces

Consume the integrated SB-01 `ResolvedCalculationInput`/outcome contracts (or their published exact names). Expose the versioned pure calculation entry point and line explanations, part/assembly subtotals, separate setup, issue list and completeness state. Prices/rates are already server-resolved inputs; this crate performs no catalog lookup. Publish calculator version and numerical validation behavior for SB-03. Any contract change goes through SB-01/coordinator review before dependent code changes.

## Ownership

Own `crates/solidbom-costing/` and tests in that crate’s existing test module. SB-01 owns initial workspace/dependency registration; reserve later root manifest/lockfile or layer edits through the coordinator. Work in the dedicated user-created Conductor workspace assigned to this package. Do not rename its branch without an explicit request. Only one package owns a shared file at a time; ask the coordinator to reserve an integration edit before changing an unlisted shared file. SB-00 owns shared execution/bootstrap documents. Never modify generated files. Run `cargo xtask ci` before every commit; do not treat a package-specific check as a substitute. Do not claim unrun tests passed.

## Acceptance

- Ideal fixture: material 0.132192, overhead 0.0066096, production 1, part subtotal 1.1388016, three-part assembly 3.4164048 and separate setup 60 CNY, within 0.0000001 CNY.
- At 60 seconds: part 2.1388016 and assembly 6.4164048; prior input values remain unchanged.
- Test missing density/material/cycle, explicit permitted zero, invalid negatives/cavities, arithmetic overflow, allowance once, setup once, incomplete outcomes and unsupported scope.
- Demonstrate assembly totals derive from unrounded values and reviewed manual volume uses the same formula. Run the crate suite and applicable layer/clippy checks.
