# SB-03 — Central persistence and API

## Objective

Provide the real persistent development service for source files, reviewed draft inputs and immutable backend calculation snapshots, with safe explicit retry.

## Requirements

Read [Prototype specification](../requirements/cost_calculator_handover/DESKTOP_PROTOTYPE_SPEC.md) and [application specification](../requirements/cost_calculator_handover/APP_SPECIFICATION.md). The application specification overrides compatible workbook formulas; proposals are not approved behavior. The original technical implementation plan is background evidence; package boundaries and current-code corrections in these briefs govern execution. Cover central behavior for P05–P12. The prototype remains online-only; one development engineer identity does not establish production authorization.

## Dependencies

Depends on: SB-02

Dependencies mean integrated predecessor work, including transitive predecessors, not a concurrent agent’s promise or an unreviewed artifact.

## Scope

- Implement the separately isolated Rust service/workspace using the SB-01 contracts and SB-02 calculator; lock compatible server dependencies.
- Store original STEP bytes/hash, project versions, source/analysis associations, engineering inputs, annotations, immutable material/rate versions and calculation snapshots in PostgreSQL. Validate all references and contract values.
- Implement source upload/download, reference lookup, project create/load/save, calculate and historical-result retrieval routes. Resolve authoritative rates/material versions on the server.
- Commit each draft version and receipt atomically with optimistic version checks. Check idempotency before version conflict: same request/payload returns its prior response; changed payload with reused ID fails. Apply equivalent lost-response behavior to create and calculate operations.
- Use bounded uploads/timeouts, hash verification, explicit development authentication and redacted errors/logs. Never queue client writes or substitute local authoritative costs.

## Interfaces

Implement the version 1 route, persistence, request-ID/payload-hash, version and error contracts published by SB-01. Consume the integrated SB-02 pure calculator. Keep source/calculation/version associations immutable and include input and calculator versions in saved results. Provide deterministic reference seeding and explicit startup/migration/test-database configuration. Source files use server identifiers rather than client absolute paths.

## Ownership

Own `services/solidbom-server/`, its independent manifest/lockfile, migrations, service tests and package-specific service instructions. Do not alter client host or UI implementation. Reserve root CI, dependency audit or shared contract changes with the coordinator. Work in the dedicated user-created Conductor workspace assigned to this package. Do not rename its branch without an explicit request. Only one package owns a shared file at a time; ask the coordinator to reserve an integration edit before changing an unlisted shared file. SB-00 owns shared execution/bootstrap documents. Never modify generated files. Run `cargo xtask ci` before every commit; do not treat a package-specific check as a substitute. Do not claim unrun tests passed.

## Acceptance

- Fresh-database migration and seed, close/reconnect persistence, invalid-reference and stale-version rejection leave earlier state intact.
- HTTP fixture calculation matches SB-02 vectors; incomplete drafts save and yield named issues with no complete current subtotal.
- Inject committed-write/lost-response retries for create/save/calculate, reused-ID/different-payload conflicts, bad authentication, hash mismatch, oversized source and malformed inputs. Assert no duplicate records or partial writes.
- Historical snapshots remain readable after edits/recalculation; project loading returns consistent source/input/result references.
- Run isolated PostgreSQL integration and HTTP tests plus server fmt/clippy/tests separately from root CI. Tests must never reset an arbitrary database.

## Assignment gate

SB-02 and its SB-01 dependency must be integrated. Assignment includes exact version 1 API/persistence/error contracts, calculator API/version and predecessor commits. An explicitly designated isolated development/test database must be available; unresolved contract or database setup blocks assignment.

## Handoff

Supply integrated commit, service start/migration/seed commands, endpoint/token configuration without secrets, schema/calculator versions and HTTP/persistence evidence. Document failure behavior and any unrun integration cases for SB-06.
