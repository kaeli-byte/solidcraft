# SB-15 — Sourcing and manufacturing definitions

Status: in progress; the sourcing/manufacturing/attached-cost contract is locked at `8d9da8a52`
(version 1, additive to API version 2; independent-review fixes at `95b035b10`) and the service
increment is implemented at `39221b1e9`; the desktop wiring and native edit/reopen evidence are
pending and depend on the open SB-10 desktop increment. The owner instructed implementation on
issue #30 on 2026-11-09
(`https://github.com/kaeli-byte/solidcraft/issues/30#issuecomment-6752721671`).

## Objective

Define explicit sourcing, reusable manufacturing routings and attached costs at the correct part or assembly owner.

## Requirements

Read [APP_SPECIFICATION](../requirements/cost_calculator_handover/APP_SPECIFICATION.md), sections 8, 10 and 11; O04/O10/O13/O14. Compatible handover formulas do not authorize implicit sourcing or cycle bases.

## Dependencies

Depends on: SB-09, SB-10, SB-11

Use integrated reference versions, project part identities and engineering review records.

## Scope

Require purchased/manufactured sourcing for custom parts, shared within the same customer part version. Apply versioned routing templates to parts/subassemblies/product roots and edit applied routings without modifying templates. Represent ordered operations, dedicated setup duration/rate, material consumption/allowance and non-CAD cost additions with explicit quantity/unit/category. Preserve assembly-operation ownership and CAD hierarchy. Cost evaluation belongs to SB-16; coordinated activation belongs to SB-19.

## Interfaces

Lock routing/operation identities, cycle basis and cavity conversion, source/template-version links, sourcing and attached-cost schemas. Provide typed draft-edit commands and explicit affected-part/product references. Pin selected production/setup rate versions; no volume-driven manufacturing assumptions or automatic template adoption.

## Ownership

Own proposed sourcing/routing/attached-cost server and client modules and area tests. Reserve contract extensions, migrations, command registration and shared catalog adapters with the coordinator. SB-09 owns template/reference authorization; do not independently alter its version lifecycle. Own `execution/SB-15.md` only.

## Acceptance

- Editing one shared part's draft routing is visible at its occurrences; another customer revision stays separate and accepted snapshots remain unchanged.
- Editing an applied template leaves the template and other instances unchanged. Missing cycle/rate data remains explicit; cavity adjustment occurs only for its declared basis.
- Assembly installation/testing stays at the parent. Packaging/adhesive cost additions do not create CAD nodes. Capture native edit/reopen evidence and run contract/API tests.

## Assignment gate

Require integrated predecessors, locked sourcing/routing/cycle/unit and template-copy contracts, reserved shared edits and an assigned base commit. Set operation-specific zero/missing validation explicitly; do not inherit spreadsheet defaults.

## Handoff

Record schema versions, ownership and quantity/cycle semantics, affected-product facts, fixtures and actual checks/evidence. Supply SB-16 with complete draft inputs while preserving SB-19 activation boundaries.
