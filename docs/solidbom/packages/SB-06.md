# SB-06 — Native service adapter and versioned controller

## Objective

Connect persistent backend work and local CAD analysis to a nonblocking, source-bound desktop controller with honest saved/current/stale states.

## Requirements

Read [Prototype specification](../requirements/cost_calculator_handover/DESKTOP_PROTOTYPE_SPEC.md) and [application specification](../requirements/cost_calculator_handover/APP_SPECIFICATION.md). The application specification overrides compatible workbook formulas; proposals are not approved behavior. The original technical implementation plan is background evidence; package boundaries and current-code corrections in these briefs govern execution. Own integration for P06–P13 and application-command access. No silent retry queue, offline authoritative edits or local production costing.

## Dependencies

Depends on: SB-03, SB-04, SB-05

Dependencies mean integrated predecessor work, including transitive predecessors, not a concurrent agent’s promise or an unreviewed artifact.

## Scope

- Implement native transport and the portable host/controller contracts, wired through optional `Services`; update desktop/web/default hosts within reserved files. No HTTP/database dependency enters portable libraries.
- Implement typed SolidBOM application-command dispatch shared by panel, desktop control and MCP, with capability errors when absent and explicit async job/status replies. No programmatic dialogs or mixed CAD/backend rollback claims.
- Separate import/review, save and calculation states. Bind each job to project/revision, source/analysis key, local edit generation and request ID; selection is not a response destination.
- Save current input generation before calculating its returned version. Edits during save remain dirty; late responses cannot become current for newer inputs or another project. Retain exact request/payload for explicit idempotent retry.
- Reopen by project ID: fetch/verify original bytes, rebuild geometry, restore verified mappings/UUIDs and saved snapshots, and bind policy. Do not replace saved results with an automatic recalculation.
- Run analysis/service jobs outside the modal file-load busy path; keep selection/navigation available, use bounded queues/timeouts/repaint wakeups and handle spawn failure without synchronous fallback.

## Interfaces

Consume the integrated SB-01 commands/host/jobs, SB-03 service, SB-04 import/selection/exact-measurement and SB-05 binding/policy APIs. Implement the portable controller and host completion adapter without duplicating arithmetic. Commands return the published job/result envelopes. Store engineering annotations and manual reviewed measurements in draft inputs. Keep current-record state independent of active selection; invalidate/discard completions on session/source/generation mismatch.

## Ownership

Own `apps/solidcraft/src/solidbom_client.rs` and `crates/ui-egui/src/solidbom/{state.rs,jobs.rs}` plus area controller tests. Reserve host constructors/Services, application command/control/MCP dispatch, batching and shared module files with the coordinator. SB-07 owns panel rendering; do not build it here. Work in the dedicated user-created Conductor workspace assigned to this package. Do not rename its branch without an explicit request. Only one package owns a shared file at a time; ask the coordinator to reserve an integration edit before changing an unlisted shared file. SB-00 owns shared execution/bootstrap documents. Never modify generated files. Run `cargo xtask ci` before every commit; do not treat a package-specific check as a substitute. Do not claim unrun tests passed.

## Acceptance

- Controlled-channel tests cover selection/tab/project changes, edit-during-save, late obsolete responses, failed writes retaining edits, version conflict and explicit retry without duplicate records.
- Exercise real service save/load/calculate using verified source mapping and policy binding; historical results remain readable and failed saves never appear saved.
- No-service capability tests and wasm checks pass; worker spawn failure and request timeout are visible failures.
- Analysis/network pending state permits navigation/selection; deterministic tests use barriers/channels, while P13 wall-clock evidence belongs to SB-08.
- Desktop control/MCP can invoke the same business actions without dialogs; unsupported transactional batch combinations are rejected.

## Assignment gate

SB-03, SB-04 and SB-05 must all be integrated, including their transitive dependencies. Assignment names exact contract version and three integration commits, confirms a running test service/database, and reserves all shared host/control files. Unmerged predecessor branches do not satisfy the gate.

## Handoff

Supply integrated commit, controller/command APIs, native host setup, completion/state-transition evidence, actual end-to-end integration results and outstanding limitations. Release shared reservations and provide SB-07 the rendering-independent state/action contract.
