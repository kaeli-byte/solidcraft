# SB-12 — Tube and protection extraction

Status: planned; not ready for assignment.

## Objective

Extract the exact geometry needed for tube/protection costing and engineering feasibility, with independently assessed accuracy.

## Requirements

Read [APP_SPECIFICATION](../requirements/cost_calculator_handover/APP_SPECIFICATION.md), section 7, O07 and scenarios 7–8; [BENCHMARK_REFERENCE](../requirements/cost_calculator_handover/BENCHMARK_REFERENCE.md) is historical inventory, not accuracy evidence.

## Dependencies

Depends on: SB-08

Use integrated prototype mapping, exact measurement and nonmodal job contracts.

## Scope

Analyze constant-diameter tubes for OD/ID, developed centerline length including arcs, exact bend count and each centerline radius. Supply tangent-to-tangent straight lengths, straight ends and end-association evidence; measure curved wear/thermal protection length. Preserve source binding and missing/unsupported results. Automatic varying-diameter measurement and recognition classification are excluded. Meshes cannot decide authoritative geometry.

## Interfaces

Lock versioned extraction inputs/results, per-bend identities, units, source associations, diagnostics and cancellation/completion rules. Expose background analysis with immutable source/algorithm identity and exact-geometry measurements. Return unavailable values explicitly; downstream review supplies manual completion without claiming extraction success.

## Ownership

Own proposed engine `solidbom/extraction` modules and existing relevant tests; changes to geometry/kernel boundaries require a separately reserved integration surface and repository kernel/solidcore rules. Do not bypass paused-kernel policy. Shared manifest types and UI jobs are reserved to their owners. Own `execution/SB-12.md` only.

## Acceptance

- Independently specified analytic cases cover straight and bent tubes, each radius, multiple bends, open/unsupported inputs and protection curves; bend count must match exactly.
- Every nonzero reference dimension passes relative error ≤0.001; 1,000 mm accepts 999–1,001 mm inclusive. Display tessellation changes cannot change the business result.
- Record actual independently referenced customer-case accuracy, coverage, sizes and timing; do not derive expected values from this extractor or claim inventory as a benchmark. Capture native/job evidence and actual relevant checks.

## Assignment gate

Implementation/benchmark assignment requires integrated SB-08, locked extraction contracts/algorithm scope, analytic fixtures and permitted kernel integration. It may collect real measurements and timings to establish coverage/performance targets. Independently verified customer references and a zero-reference convention are required for the applicable accuracy comparisons. Final customer acceptance requires recorded benchmark evidence and owner-agreed coverage/performance targets derived from it. Missing reference evidence blocks final verification, not analytic extraction development; synthetic checks alone cannot make this package verified. The fixed ±0.1% tolerance is never negotiated away.

## Handoff

Record build/algorithm versions, fixture provenance, per-measurement results, unsupported cases, performance measurements and exact checks. Supply versioned outputs to SB-13/SB-14 without unsupported recognition claims.
