# SB-01 — Contracts and integration foundations

## Objective

Publish the version 1 contracts and the minimal integration foundations that let subsequent packages work against one reviewed interface. This package does not implement costing, persistence, CAD extraction or the review UI.

## Requirements

Read [Prototype specification](../requirements/cost_calculator_handover/DESKTOP_PROTOTYPE_SPEC.md) and [application specification](../requirements/cost_calculator_handover/APP_SPECIFICATION.md). The application specification overrides compatible workbook formulas; proposals are not approved behavior. The original technical implementation plan is background evidence; package boundaries and current-code corrections in these briefs govern execution. Cover the contract needs of P01–P14 without expanding the prototype into full MVP.

## Dependencies

Depends on: SB-00

Dependencies mean integrated predecessor work, including transitive predecessors, not a concurrent agent’s promise or an unreviewed artifact.

## Scope

- Define portable, versioned identities, source and analysis manifests, draft engineering inputs, issues, calculation requests/results, job envelopes and host capabilities. Distinguish missing values from explicit zero; use decimal strings and explicit units.
- Specify reviewed classification, sourcing, material/rate versions, material overhead, allowance, quantity expansion, separate setup and annotation storage. Include exact source/input/version binding and stale-result semantics.
- Publish HTTP request/response, idempotency, optimistic concurrency and error contracts; stable source identity must be distinct from generated CAD occurrence IDs.
- Register crate/workspace/layer foundations, native-only host seams and no-service behavior. Add typed SolidBOM command/schema scaffolding and a documented dispatch path for UI, desktop control and MCP. Do not implement business operations here.
- Document how service commands avoid CAD undo and mixed transactional batches; an absent service returns a capability error rather than opening a dialog.

## Interfaces

Publish version 1 contract artifacts under `docs/solidbom/contracts/` and matching portable types in `crates/solidbom-contract/`. Contracts must define `SourceRef`, `AnalysisKey`, definition/occurrence/geometry bindings, `Measurement`, draft inputs, save/calculation requests and receipts, immutable snapshots, named issues, and job completion envelopes. Define `SolidBomHost` submission/polling, ownership, bounded queues, cancellation and wakeup semantics. Define the typed `solidbom.*` command IDs and their input/output schemas before downstream assignment. These names describe interfaces to establish, not existing or locked APIs. Reuse the application-command dispatch pattern in `SolveApp::run`; explicitly cover host-dispatched commands that do not pass through `Session::execute`.

## Ownership

Own `crates/solidbom-contract/` and the initial version 1 contract documents. Reserve root `Cargo.toml`/`Cargo.lock`, engine/UI/desktop manifests, `xtask/src/layers.rs`, shared module declarations, command/schema registration, `Services`, desktop/web host constructor scaffolding and CI foundation edits with the coordinator. Publish the exact shared-file changes and release reservations before downstream work. Work in the dedicated user-created Conductor workspace assigned to this package. Do not rename its branch without an explicit request. Only one package owns a shared file at a time; ask the coordinator to reserve an integration edit before changing an unlisted shared file. SB-00 owns shared execution/bootstrap documents. Never modify generated files. Run `cargo xtask ci` before every commit; do not treat a package-specific check as a substitute. Do not claim unrun tests passed.

## Acceptance

- Serialization and schema checks cover decimal strings, unsupported versions, units, missing/zero values and nonfinite or overflowing geometry conversion.
- Command discovery/schema and absent-host tests establish portable application-command behavior without network or dialogs.
- Layer and wasm checks pass for the foundations; native service dependencies do not enter portable CAD libraries.
- Contract artifacts include version, exact paths and integration commit references; required fields for every prototype calculation and save/reopen scenario are representable.

## Assignment gate

SB-00 must be integrated and its execution/ownership records available. The coordinator assigns this package first. No downstream package is assignable merely because this brief lists proposed interfaces: publish and integrate the version 1 contracts and foundation commit first.

## Handoff

Give the coordinator the integrated commit, contract artifact references/version, exact command and host interfaces, checks and limitations, and released shared-file reservations. Record any unresolved contract decision as a blocker rather than sending downstream agents incompatible assumptions.
